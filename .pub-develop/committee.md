# Maintainer committee

## Membership and protected files

Record the committee in `.pub-develop/committee.json` on the protected governance ref. The file contains an increasing `revision` and `members` tied to the numeric GitHub user IDs in `maintainers`. Each member has a `user_id` and a list of explicit `permissions` chosen from `vote_secondary`, `vote_membership`, `manage_members`, and `change_protected_paths`. For voting delegations, the runner records the member ID, agent ID, ballot ID, and expiration time. Code review delegation grants no committee permissions. The owner initializes the membership list and retains approval authority over changes to membership and delegations.

The `protected_paths` list covers committee and project configuration, governance policy, points rules, `CODEOWNERS` files, required checks, and privileged workflows. Use Git paths relative to the repository root or directory paths ending in `/**` to protect every descendant. The runner compares actual paths from the Git diff and checks both paths on a rename. Reject contributor requests that touch protected paths. The owner or a member with `manage_members` must use a separate governance procedure to change membership or `protected_paths`. When a member submits a change, the owner approves it independently. Other protected files require `change_protected_paths` and owner review. Evaluate the currently effective rules before applying the change, including whether the requester would expand their own permissions. Enforce ref and workflow protection outside the candidate pull request. [GitHub branch rules](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets)

## Voting on secondary objectives

1. If an issue proposes a feature that expands scope while preserving the core objectives, the owner's agent separates it into a secondary proposal. Record the issue link, scope, effort weight, impact, dependencies, and cost to core work. Refer any change to the core direction to the owner.
2. The runner opens a ballot with a unique ID and status `pending_vote` against the current committee revision. Freeze the proposal text, weight, list of eligible voters without conflicts, and deadline. Changes to scope or weight reopen the ballot under a new revision.
3. Accept `approve`, `reject`, or `abstain` from a member with `vote_secondary` or an agent explicitly delegated by that member for the ballot. Count each member's latest valid vote. Exclude the proposer and direct beneficiaries. Reopen with an updated roster if membership or eligibility changes before closing.
4. By default, voting lasts seven days. At least half the eligible members must participate, rounded up, with a minimum of two. Approval requires support from more than half of all eligible members. Abstentions count toward participation and remain in the denominator for approval. If fewer than two members are eligible, defer the proposal until the committee can vote. Record `expired` if participation falls short, `rejected` if participation is sufficient and approval falls short, or `approved` if both conditions are met. Save the counts and the ballot revision. An approved objective enters the development report. Create its tasks after assessing feasibility and capacity, then record `accepted` or `partially_accepted` on the issue when appropriate.

## Nominating a maintainer

Once a contributor earns **20 active points from at least four verified contributions in the last 180 days**, the owner's agent can propose a nomination using the points record and examples of effective collaboration or review. Calculate the time window from the original award date when an entry is corrected. The [committee template](committee.example.json) uses `nomination` for the thresholds and `voting_period_days` for the deadline. An authorized maintainer agent can prepare a supporting professional summary. External experience provides context. The nomination is based on work within the project.

After the nominee consents, hold a ballot under the same rules for members with `vote_membership`. Exclude the nominee and anyone with a conflict of interest. If approved, the owner or a member with `manage_members` submits a protected membership change. Delegation takes effect after owner approval and after the membership, permissions, and effective time are recorded. Suspending or revoking a delegation blocks new votes from that delegate and triggers reevaluation of pending merges.
